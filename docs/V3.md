# AutoByte v3

v3 replaces "a folder of scripts and a menu" with **one engine**: a PowerShell module of
small, tested *tasks*. One `abyte` command serves technicians, end users and Datto RMM, and
writes an HTML report. v2 (`AutoByte.ps1`, `Scripts/`) keeps working alongside it.

```
            +--------------------- AutoByte module (src/AutoByte) ----------------------+
 abyte ---> |  Checks (read-only)  ->  Findings  ->  suggested Fix tasks (idempotent)   |
 Datto  --> |  Engine: Test -> Repair -> verify, -WhatIf, exit codes, log, config      |
 AI agent ->|  Adapters: the only code that touches Windows (mocked in tests)          |
            +---------------------------------------------------------------------------+
                   |                         |                          |
             HTML report               JSON (RMM/AI)          %ProgramData%\AutoByte\Logs
```

## Concepts

| Term | Meaning |
|---|---|
| **Check** | Read-only task. Returns findings; never changes the PC. |
| **Finding** | One problem or fact: `Code` (stable id, e.g. `disk.low`), `Severity` (Info/Warning/Critical), title, detail, and the `FixTask` that resolves it. |
| **Fix** | Task that changes the PC. `Test` decides if it is needed; `Repair` runs only then; `Test` runs again to **verify**. Running a fix twice is safe. |
| **Scan** | All checks, plus a summary and the list of suggested fixes. |
| **End-user safe** | Fixes non-technical users may run from the menu (temp clean-up, DNS flush, print queue). Everything else says "needs your IT support". |

## Commands

```powershell
abyte                       # end-user menu: 1 check my PC, 2 fix what's safe, 3 open report
abyte scan                  # all checks, human summary
abyte scan --report --open  # ... plus HTML report, opened in the browser
abyte scan --json           # machine-readable (RMM, scripts, AI)
abyte scan --fail-on critical   # exit 1 if any critical finding (for monitors)
abyte fix clean-temp-files --whatif      # preview
abyte fix clean-temp-files               # asks y/N
abyte fix --suggested --yes              # run every fix the scan suggested
abyte fix repair-system-files --param Force=true --yes
abyte list [--kind fix] [--json]
abyte legacy DiskCleaner --whatif        # run a v2 script (hash-verified, via the v2 launcher)
```

Exit codes: `0` ok · `1` a fix failed, or findings matched `--fail-on` · `2` usage error ·
`3010` a restart is required. A check that cannot run (e.g. Defender cmdlets absent) is shown
in the output but does not fail the job.

### Event Viewer analysis (`event-logs`)

Reads the **System**, **Application** and **Setup** logs plus the **Defender**, and
**Diagnostics-Performance** operational logs for the last 7 days (`--param Days=14`), and matches
known problem events by provider and event id (never by message text, so any Windows language
works). Each match becomes a finding with a plain explanation and the fix task that addresses it:

| What it finds | Events | Fix it points to |
|---|---|---|
| Blue screens, decoded by stop code (e.g. `0x9F` driver power failure) | BugCheck 1001 | `install-driver-updates`, `repair-system-files` or `repair-disk-errors` by stop code |
| Unexpected shutdowns | Kernel-Power 41, EventLog 6008 | — |
| Bad blocks, I/O retries, NTFS corruption | Disk 7/51/153, Ntfs 55/98/130 | `repair-disk-errors` |
| Storage controller resets (freezes) | storahci/stornvme 129 | `install-driver-updates` |
| Hardware errors | WHEA-Logger 1/17/18/19/47 | `install-driver-updates` (BIOS/chipset) |
| Graphics driver resets, drivers failing to load | Display 4101, Kernel-PnP 219 | `install-driver-updates` |
| Services that keep failing | Service Control Manager 7000–7034 | `reset-windows-update`, `clear-print-queue` or `start-core-services` |
| Apps that crash or freeze (grouped by app and module) | Application Error 1000, Hang 1002, .NET 1026 | `update-apps`; Windows components → `repair-system-files` |
| Windows Update failures, decoded by error code | WindowsUpdateClient 20, Setup log | `repair-system-files`, `reset-windows-update`, `clean-temp-files` or `reset-network-cache` |
| DNS timeouts, time sync, domain controller, Group Policy | DNS Client 1014, Time-Service, NETLOGON 5719, GroupPolicy | `reset-network-cache`, `resync-time` |
| Temporary user profile | User Profile Service 1511/1515 | technician |
| Malware detected / clean-up failed | Defender 1116/1118/1119 | technician |
| Apps, drivers and services that slow start-up | Diagnostics-Performance 101–109 | `install-driver-updates` for drivers |

Known-harmless noise (DCOM 10016 and similar) is excluded. Rules live in
`src/AutoByte/Private/EventRules.ps1`; adding one is a few lines.

### Why is it slow? (`performance`)

Samples CPU, memory commit and disk activity over three seconds and names the processes using
the most; flags Power saver, Windows on a spinning hard disk, many start-up apps and a slow last
boot (with `event-logs` naming the culprits).

### Drivers, updates, CVEs and apps

- `drivers` lists devices Device Manager flags (with the "Code NN" meaning) and driver updates
  Windows Update offers. `install-driver-updates` installs those (signed, Microsoft-published).
- `security-updates` asks Windows Update — or the WSUS/Intune source in force — what security
  updates are missing; `install-security-updates` installs them (`--param All=true` for every
  update). This is how CVE fixes are applied.
- `cve-exposure` compares this PC's exact build (e.g. `10.0.26100.2894`) with the fixed build
  Microsoft publishes for every Windows CVE of the last 3 months (MSRC security update feed,
  no key needed) and marks CVEs on CISA's Known Exploited Vulnerabilities list as critical. Feeds
  are cached daily in `%ProgramData%\AutoByte\Cache`, so new CVEs are picked up automatically
  every day. Offline, it says so and `security-updates` still reports missing patches.
- `app-updates` lists apps with newer versions (winget, works as SYSTEM) and flags browsers, PDF
  readers, runtimes, archivers and remote-access tools; `update-apps` upgrades them
  (`--param Ids=Google.Chrome` or `--param Exclude=...`).

These fixes are not "end-user safe": they install software and may restart apps. In Datto, run
them as targeted fixes or in a maintenance window, e.g. `abAction=fix`, `abTask=install-security-updates`.

`abyte list` always shows the current list with descriptions.

## Install

On one PC (elevated PowerShell):

```powershell
$i = Join-Path $env:TEMP 'Install-AutoByte.ps1'
Invoke-WebRequest 'https://raw.githubusercontent.com/deep1ne8/misc/v3.0.0/install/Install-AutoByte.ps1' -OutFile $i -UseBasicParsing
powershell -NoProfile -ExecutionPolicy Bypass -File $i -AddToPath -CreateShortcut
```

The installer downloads `src/AutoByte/files.sha256` from the release tag, verifies every file
against it, stages them, and only then installs. A tampered file, an unexpected path or a
version mismatch aborts with nothing installed. Re-running is a no-op when already current.
Offline: `-SourcePath <copy of the repo>`. Preview: `-WhatIf`.

`-CreateShortcut` adds **AutoByte PC check-up** to the Start menu for end users.

## Datto RMM

**1. Create the component** (Automation → Components → New → PowerShell):
- Script: paste `datto/AutoByte-Datto.ps1`.
- Attach `install/Install-AutoByte.ps1` (optional; otherwise endpoints fetch it from the tag).
- Variables:

| Variable | Type | Default | Purpose |
|---|---|---|---|
| `abAction` | Selection: scan, report, fix, legacy | scan | What to do |
| `abTask` | String | | Fix id(s), comma-separated, or `suggested` |
| `abWhatIf` | Boolean | false | Preview fixes only |
| `abFailOn` | Selection: None, Warning, Critical | None | Alert when findings reach this level |
| `abUdf` | String | | UDF number (1-30) to receive a one-line summary |
| `abVersion` | String | 3.0.0 | AutoByte version to install/use |
| `abScript` | String | | v2 script name (for `abAction=legacy`) |

**2. Typical jobs**
- *Nightly health scan*: `abAction=scan`, `abUdf=10` → UDF 10 shows `AB 3.0.0 scan: 1 critical, 2 warning | 2026-11-16 02:00`.
- *Self-heal*: `abAction=fix`, `abTask=suggested` (add `abWhatIf=true` for the first week).
- *Targeted fix*: `abAction=fix`, `abTask=clear-print-queue`.
- *Monitor* (component monitor): `abAction=scan`, `abFailOn=Critical` → exits 1 and raises an alert;
  the `<-Start Result->` block carries the status line, `<-Start Diagnostic->` the full JSON.

**3. Tune thresholds per site** with site/component variables named `AB_<Setting>`, e.g.
`AB_DiskWarnPercent=20`, `AB_UptimeWarnDays=30`, `AB_ConnectivityHosts=www.microsoft.com,portal.client.com`.
Settings: `DiskWarnPercent` 15, `DiskCriticalPercent` 5, `MemoryWarnPercent` 10, `UptimeWarnDays` 14,
`EventErrorWarn` 25, `EventLookbackDays` 7, `DefenderSigMaxDays` 3, `TimeSkewWarnSeconds` 60, `TempFileMinAgeDays` 7,
`ConnectivityHosts`, `CpuWarnPercent` 85, `CommitWarnPercent` 90, `DiskBusyWarnPercent` 90, `BootWarnSeconds` 120,
`StartupItemsWarn` 15, `CveCheck` 1 (0 turns the CVE check off), `CveMonths` 3, `CveFeedUrl`, `KevFeedUrl`. Non-secret defaults can also live in `%ProgramData%\AutoByte\config.json`.

## AI agent (optional)

`AutoByte-Agent` now has `health_scan` (runs the v3 scan, read-only) and `run_task <id>`
(runs one v3 fix after you type `y`). Its instructions tell it to scan first and prefer v3
tasks over raw PowerShell. Without the module it falls back to the v2 tools.

## Adding a task

Create `src/AutoByte/Tasks/<Category>/<id>.task.ps1` returning one hashtable:

```powershell
@{
    Id          = 'my-check'            # lowercase-kebab-case, unique
    Name        = 'Human name'
    Kind        = 'Check'               # or 'Fix'
    Category    = 'System'
    Description = 'One sentence shown in abyte list and the report.'
    Test        = {
        param($Ctx, $P)                 # $Ctx.Config = settings, $P = task parameters
        # Checks: emit New-AbFinding ... (nothing = healthy)
        # Fixes:  return @{ Needed = $true/$false; Reason = '...' }   ($Ctx.AfterRepair is $true when verifying)
    }
    # Fixes only:
    # Repair = { param($Ctx, $P) ...; @{ RebootRequired = $false } }
    # RequiresAdmin = $true; EndUserSafe = $false; RebootMayBeRequired = $false; Parameters = @{ Force = $false }
}
```

Rules: touch the system **only** through the adapters in `Private/Adapters.ps1` (add one if
needed), keep it Windows PowerShell 5.1-compatible, add tests in `tests/v3/`, then run
`pwsh ./build/Build-AutoByteModule.ps1` and `pwsh ./build/Invoke-LocalCI.ps1`.

## Releasing v3

1. Bump `ModuleVersion` in `src/AutoByte/AutoByte.psd1` and the default `-Version` in
   `install/Install-AutoByte.ps1` / `abVersion` in `datto/AutoByte-Datto.ps1`.
2. `pwsh ./build/Build-AutoByteModule.ps1`, local CI, merge.
3. Tag the merged commit `v<version>` and push the tag. Endpoints install only tagged versions.
